## hs-card 在 Android 不显示文字（index 首页）
- 原因：uni-app x（uvue/vapor）中 view/容器内**裸文本不渲染**，文字必须包 `<text>`；web 端浏览器会渲染裸文本所以可见。hs-card 本身挂载正常（编译产物 GenUniModulesHsDesignComponentsHsCardHsCard），只是文本节点没进 Android 包。
- 修复：`pages/index/index.uvue` 6 处 `<hs-card>文字</hs-card>` → `<hs-card><text>文字</text></hs-card>`。
- 规范：hs-design 组件库中 hs-button/hs-input 为 .uvue，hs-card/hs-form/hs-form-item 为旧 .vue（仅模板+样式，Android 也能渲染）；**调用方传裸文本需自行包 text**。

## hs-stomp "回调函数已释放，不能再次执行"（16:25 运行时报错）
- 机制（HBuilderX 4.25+）：UTS 插件**导出方法**的回调参数默认"触发一次后自动回收"；若插件把回调长期保存并在后续多次触发（如 socket 收到消息帧时调用），必须用 `@UTSJS.keepAlive` 装饰器（或方法名以 `on` 开头且仅一个回调参数）。
- 修复：`uni_modules/hs-stomp/utssdk/index.uts` 的 `subscribe()` 前加 `@UTSJS.keepAlive`。custom compile exit 0 通过。
- 同类隐患排查：hs-mqtt 的 subscribe 不收回调（消息走内部 onMessageReceive 属性），无此问题；其它 hs-* 若再报同错，对导出方法加 `@UTSJS.keepAlive` 即可。
- 待真机验证：stomp 页连续收到 ≥2 条消息不再报错（设备需重新上线）。

## 自定义基座运行问题（重要）

- 现象：提示"uts插件依赖的原生配置或三方SDK在运行至标准基座时不能生效，需使用自定义基座"。
- 根因链：
  1. 运行模式没选自定义基座：`.hbuilderx/launch.json` 记录 `playground: "standard"`；CLI `launch app-android` 默认 `--playground standard`，需显式加 `--playground custom`。
  2. 补上 `--playground custom` 后报"项目下未找到自定义运行基座"：`unpackage/debug/android_debug.apk` 是 **HBuilderX 5.14** 时期（2026-07-07）打的自定义基座（apk 内 `assets/uni-app-x/hxversion.data` = `{"hxVersion":"5.14"}`），当前 HBuilderX 为 **5.24**，uni-app x 编译器与基座版本必须严格一致 → 旧基座被判定不可用。
- 解决：必须用当前 HBuilderX 5.24 在 GUI 重新制作自定义调试基座（发行/云打包界面勾选"制作自定义调试基座"，需 DCloud 账号，CLI 无法云打包）；完成后用 `cli launch app-android --project <abs路径> --playground custom` 或 GUI"自定义基座运行"。
- 提醒：只改 uvue/uts 页面与插件代码**无需重打基座**；修改 `config.json`/`AndroidManifest.xml`/libs 原生依赖才需重新制作。
