# EMR 打印分页引擎逻辑全解

> 对应实现：`src/utils/emrPagination.ts`（分页引擎）、`src/utils/emrPrint.ts`（打印输出）、
> `src/components/EmrPrintDialog.vue`（预览弹窗）、`src/components/EmrDesigner.vue`（入口）、`src/style.css`（打印样式）。
> 本文与当前代码一一对应，含历次留白 Bug 的根因与结论。

## 一、总体架构与数据流

```
EmrDesigner.openPrintDialog()
  └─ 取编辑器 .emr-content 元素 → 宿主注入的 showPopup(EmrPrintDialog, { source, settings })
       ├─ 预览：buildPrintContainer(source, settings)                ← EmrPrintDialog.renderPreview
       ├─ 打印：printEmrDocument(source, settings, { copies })       ← 浏览器 window.print()
       └─ PDF ：saveEmrDocumentAsPdf(source, settings, { copies })   ← snapdom 截图 + jsPDF 拼图
                          │
                          ▼（三者共用同一棵输出树）
              buildPrintContainer ──► paginatePrintPages（真实切片分页）
```

核心设计决策（所见即所得的三大支柱）：

1. **真实切片分页**：不依赖浏览器自动分页，先在离屏探针页里按真实排版高度把正文切成"每页一块 HTML"，
   输出端只是把切片装进固定尺寸的纸张盒。
2. **边距内建到页盒**：`@page { margin: 0 }`，纸张尺寸与四边距全部由 `.emr-print-page` 的
   `width/height(mm) + padding(mm)` 实现，保证屏幕预览与打印输出像素级一致。
3. **预览 / 打印 / PDF 同源**：三个出口消费同一棵 `buildPrintContainer` 生成的 DOM，杜绝"预览对、打印错"。

## 二、分页引擎知识点（emrPagination.ts）

### 2.1 输入准备：克隆与清洗

| 知识点                                | 说明                                                                                                                                                                                                                      |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cloneNode(true)` 克隆 `.emr-content` | 分页在克隆上操作，绝不触碰编辑器实时 DOM                                                                                                                                                                                  |
| `syncFieldValues`                     | **`cloneNode` 不会复制 input/textarea/select 的"实时值"**（DOM property ≠ attribute），必须先把 `.value` 写回 `value` 属性 / `textContent` / `selected`，否则克隆件里字段全空                                             |
| `sanitizePrintClone`                  | 剥离编辑态痕迹：`contenteditable`、`tabindex`、`id`、ProseMirror 选区类（`ProseMirror-selectednode`、`selectedCell` 等）、测量用 `.measure-span`、`button`。目的：测量环境 = 输出环境，任何编辑态样式差异都会造成测高偏差 |
| 页眉/页脚抽取                         | `pm.querySelector(":scope > .emr-header / .emr-footer")` 取 `innerHTML` 后从正文移除；全文档共用，由输出端逐页重复                                                                                                        |
| 正文块节点                            | `pm.children` 即顶层块：`P/H1-H6/DIV.tableWrapper` 等                                                                                                                                                                     |

### 2.2 纸张与可用高度

- `getPaperDimensionsMm`：按 `PAGE_SIZE_DIMENSIONS` 取毫米宽高；**横向（landscape）时交换宽高**；`Custom` 纸张按 A4 兜底。
- **离屏探针页（probe）**：`.emr-print-page` 固定纸张尺寸 + 边距 padding，挂在
  `.emr-paginate-stage`（`position:fixed; left:-100000px; width:0; height:0; overflow:visible`）里。
  探针与最终页盒**同尺寸、同 CSS 作用域**（都带 `.emr-standard-print` 类），排版结果可直接复用。
- 探针内同样放入页眉盒 / 正文盒 / 页脚盒三段 → **`available = bodyBox.clientHeight` 天然扣除了页眉页脚占位**，正文切片高度不会与页眉页脚重叠。
- `waitForLayout`：`document.fonts.ready` + **两轮 requestAnimationFrame**，确保字体落位、布局收敛后再测量（字体迟到是测高偏差的常见来源）。

### 2.3 硬分段：显式分页符

`segmentByPageBreak`：按 `.page-break` 节点把块序列切成多个"硬分段"，**每个分段独立走填页流程**，
分段结束必然换页。分页符本身不输出（样式里 `.page-break` 被 `display:none` 隐藏，分页由真实切片体现）。

### 2.4 累加器 acc：真实渲染溢出探测

填页不使用"算术累加高度"，而是用一个**隐藏的累加器**做真实渲染探测：

- `acc`：`ProseMirror emr-print-content` 类（与正文同 CSS 作用域）、宽度 = 探针正文盒实宽、
  `position:absolute; visibility:hidden; overflow:visible`。
- `isOverflow()` = `ceil(acc 渲染高度) > available - 1`（1px 容差）。
- `usedHeight()` = `ceil(acc 渲染高度)`，即"当前页已用高度"。
- 每页内容 = `acc.innerHTML`（`pushPage` 取出后 `replaceChildren()` 清空）。

**关键经验：测量与判定必须在同一渲染环境完成。** 早期版本"在探针里量行高、回输出端做加和比较"，
因两处渲染环境差异（外边距合并、边框、单元格内段落边距等）产生几 px~几十 px 误差，导致整块被提前挤到
下一页、页面底部大片空白。现在表格路径完全以 acc 的真实渲染高度为准。

### 2.5 块级填页主循环（segmentPages）

对分段内每个块节点，按优先级走三条路径：

```
tryAppend(node.outerHTML) 成功 ──► 整块放入当前页（快速路径）
        │失败
        ▼
node 是 .tableWrapper ──► placeTable（表格贪心填页）
        │否
        ▼
splitNodeByLines(node) 得到行片段 ──► 逐行 appendHtml；不可拆则整块 appendHtml
```

- `appendHtml`：放不下且 acc 非空 → 先 `pushPage` 换页再放入；**单块超页高时独占一页**（超出部分被页盒 `overflow:hidden` 裁剪）。
- 分段结束 `acc` 有残料（或分段为空）→ `pushPage` 收尾。

### 2.6 超高文本按"视觉行"拆分（splitNodeByLines + cloneLineHtml）

仅对 `P/H1-H6/LI` 生效，拆到**行**粒度：

1. `TreeWalker` 收集节点内全部文本节点；
2. **逐字符建 Range 取 `getBoundingClientRect`**，按 `rect.top` 相同（±1px）归并为视觉行；
   零宽字符（无 width/height 的 rect）跳过；
3. 每行用 `cloneLineHtml` 生成保留结构的 HTML：
   - `range.cloneContents()` 取行内容，再**从公共祖先向下逐层补壳**（while 循环 cloneNode(false) 包一层），
     保住变量下划线等内联样式；
   - 补回段落末尾的 `br.ProseMirror-trailingBreak`（Range 不含它，缺了会丢一行高度）；
4. 行片段逐条 `appendHtml`，天然跨页续排。

非文本块（不在标签白名单内）返回单元素数组 = 不可拆，走"整块独占一页"。

### 2.7 表格贪心填页（placeTable）★ 历次留白 Bug 的修复重心

表格是文书主体（病案首页类版式），拆分为三级粒度：**表 → 行 → 行内条带**。

1. **窄缝保护**：开始放表前，若当前页剩余 < 80px，先换页（避免页尾只塞一行）。
   阈值演进：最初"不足 1/4 页就换页"过于激进，制造了约 1/4 页的人为留白，已降为 80px。
2. **表骨架（startChunk）**：克隆整表、剥掉 `thead/tbody/tfoot`，塞一个空 `tbody` 进 acc；
   之后**逐行 clone 追加进这个活骨架**，每加一行就 `isOverflow()` 真实判定：
   - 不溢出 → 继续下一行；
   - 溢出且骨架已有行 → 撤掉本行、`pushPage` 落页、重建骨架、在新页重新追加本行。
   - 好处：一页内的表格行始终属于同一个 `<table>`（共享 colgroup/边框），不会碎成多张表。
3. **超高行拆条带（buildRowBands）**：整行放不下且骨架本行还没有内容时，尝试把该 `<tr>` 按
   "各单元格第 k 个子元素（段落）"横向切成条带行，条带间继续逐条真实测溢。
   适用场景：一个单元格装多段文字的巨型行（如"抗菌药物使用情况"行），不拆条带就只能整行挪页、
   前页底部留半页空白。
   **安全护栏（不满足即退回整行挪页）**：
   - 所有单元格内容均为块级元素（含裸文本/内联节点时拆会丢内容）；
   - 至少 2 个条带才有拆的意义；
   - 单元格含 `rowSpan/colSpan` 合并时不拆（跨页会错位）。
   - 注：`rowSpan` 是 `HTMLTableCellElement` 属性，`HTMLTableRowElement` 上没有（编译期踩坑点）。
4. **不可拆的超高行**：换页后独占一页，超出页高的部分被裁剪（现状取舍，见第七节）。
5. 整表能放进当前页时走不到这里——主循环的 `tryAppend` 快速路径已保留原始结构直接落页。

### 2.8 输出结构

`paginatePrintPages` 返回 `PrintParts = { pages: [{ bodyHTML }...], headerHTML, footerHTML }`，
只交出"每页正文 HTML + 全文共用页眉页脚"，页盒拼装由打印构建器负责（数据与视图分层）。

## 三、打印输出知识点（emrPrint.ts）

### 3.1 页盒组装（buildPageElement / buildPrintContainer）

- 每页一个 `.emr-print-page`：`width/height` 毫米固定 + `padding` 四边距（边距内建）；
  纵向 flex 三段：`__header`（页眉）/ `__body`（正文切片，`flex:1; min-height:0; overflow:hidden`）/ `__footer`（页脚）。
- 页码：`第 N / M` 绝对定位于页脚右侧，M = 单套总页数；
  **份数与页码是独立维度**——打印 N 份 = 整套页盒复制 N 遍（预览恒为 1 套），页码不随份数变化。
- `printMode` 为 true 时容器加 `.is-print` 类（屏外绝对定位），预览态则是普通文档流（弹窗内可见）。

### 3.2 @page 与打印隔离（printEmrDocument）

- `buildPageStyleText`：`@page { size: Wmm Hmm; margin: 0 }`——边距已在页盒内，
  **@page margin 归零是所见即所得的关键**；若留 @page margin 会二次边距 + 每页溢出。
- `buildPrintIsolationStyleText`（@media print）：
  - `body > *:not(.emr-standard-print) { display:none }`：打印时隐藏宿主页面/弹窗等一切其他内容；
  - `.is-print` 复位为 `position:static`（屏外定位不能带进打印）；
  - **`.emr-print-page { break-after: page }` + `:last-child { break-after:auto }`**：
    每个页盒恰好一张纸，末尾不多出一张空白页。
- 执行时序：挂样式与容器 → `waitForRenderReady`（字体 + 双 RAF）→ `window.print()` →
  `afterprint` 事件清理，另设 **3 秒兜底定时器**（部分浏览器 afterprint 不触发）。

### 3.3 PDF 导出（saveEmrDocumentAsPdf）

- 同一棵分页树挂屏外 → 逐页 `@zumer/snapdom` 截图（JPEG, scale 1.5）→ `jsPDF` 按页盒像素尺寸
  `format:[w,h]` 逐页 addPage + addImage。
- 因为分页是真实切片，PDF 天然按纸出页，无需 CSS 分页参与；横竖向按页盒宽高自动判断。

## 四、样式体系知识点（style.css 打印相关段）

| 规则                                                                              | 目的                                                                                                             |
| --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `.emr-standard-print .emr-print-page { overflow:hidden }`                         | 固定纸张盒，超出裁剪，防止内容撑破页面                                                                           |
| `.emr-print-content` 下 p/h1-h3/ul/li/table/th/td 的排版规则                      | **打印作用域重建排版**：克隆件脱离了编辑器 scoped 样式，必须在全局作用域复刻一份，否则探针测量与输出渲染都会失真 |
| `table { border-collapse:collapse; width:100%; table-layout:fixed }`              | 表格切片后列宽仍由 colgroup 决定，跨页宽度稳定                                                                   |
| `.emr-variable { border-bottom; background:none }`                                | 变量控件输出为"下划线纯文本"，保留书写感、去掉编辑态高亮                                                         |
| EP 控件（el-input/el-select wrapper）去框线、`pointer-events:none`                | Element Plus 控件打印观感纯文本化                                                                                |
| `.page-break/.page-break-text { display:none }`                                   | 分页标记不输出（分页已由真实切片体现）                                                                           |
| `@media print` 前半段（隐藏设计器、解除 flex/overflow、`@page margin:10mm` 兜底） | **Ctrl+P 直接打印编辑器页面的兜底**，与打印引擎路径相互独立                                                      |

## 五、弹窗层知识点（EmrPrintDialog.vue）

- `effectiveSettings`：文书原始页面设置 + 弹窗本地覆盖（纸张/方向/边距）合并，预览与输出都只消费合并结果。
- 影响纸张盒模型的设置变化 → `watch` 触发 `renderPreview()` 全量重分页；**份数不影响单页预览，不监听**。
- 预览缩放：`measureSheet` 量容器实宽实高，`updateScale` 按可用宽度等比缩小（上限 100%），
  `transform: scale()` + 外层占位盒同步缩放尺寸；`document.fonts.ready` 后重测一次（字体迟到）。
- 目标输出二选一：浏览器打印 / 另存 PDF；弹窗外壳由宿主注入的 `showPopup` 提供（emr 包不依赖弹窗实现）。

## 六、分页留白问题的演进史（4 轮修复记录，重要经验）

| 版本 | 症状                                   | 根因                                                                                   | 结论                                                                     |
| ---- | -------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| v1   | 第 1 页只有几行，表格整体从第 2 页开始 | 超高块按**整页高**切片，首切片 ≈ 整页高，装不进"已被段落占用的首页"，被整体挤到下一页  | 拆分必须考虑"当前页剩余高度"，不能只看整页高                             |
| v2   | 首页修好，但其余页底部大片空白         | 切片只在**第一次**用了剩余高度，后续切片仍按较小的固定高度切死，整页只装得下一片       | 一次性预切片不可行，必须**逐页重新测量**                                 |
| v3   | 第 2、3 页仍留白                       | 行高在探针测、在输出页用算术比较，**两处渲染环境有误差**（外边距/边框/取整），提前换页 | 放弃算术，改为**在累加器内真实渲染 + 逐行实测溢出**（placeTable 现方案） |
| v4   | 第 3 页留白（约半页）                  | 巨型单行（单元格内多段落）不可再按行拆                                                 | 增加**行内条带拆分**（buildRowBands），并加裸文本/合并单元格护栏         |

配套排查经验：

- 诊断日志用 `console.log` 而非 `console.debug`——Chrome DevTools 默认隐藏 Verbose 级别，"日志没生成"多半是被过滤级别吃掉了。
- 排查分页留白先打块清单（`tagName / class / 高度 / 行数`），一次日志即可区分"不可拆块"“分页符"“测量误差"三类根因，避免盲改。

## 七、已知边界与取舍

1. **超高单行/超大不可拆块**：独占一页，超出部分被页盒裁剪——目前不丢在"下一页"而是直接不可见，
   若业务出现此类版式需扩展（如按字符拆行、或允许条带护栏放宽）。
2. **表头跨页重复未实现**：切片后每页是独立 `<tbody>`，原 `thead` 被拍平进 tbody，不逐页重复表头。
3. **rowSpan/colSpan 行不参与条带拆分**（护栏），这类行仍可能整行挪页产生留白。
4. **Custom 纸张按 A4 兜底**（毫米维度表无 Custom 项）。
5. **嵌套表格**：只识别顶层 `.tableWrapper`，嵌套表随外层块整体处理。
6. 页眉/页脚高度在探针中已计入 `available`，但页眉页脚自身超长（超过约一页）不做保护。
7. 打印份数复制的是整套页 DOM，份数很大时输出树体积线性增长（浏览器打印场景可接受）。

## 八、术语速查

| 术语                 | 含义                                                                  |
| -------------------- | --------------------------------------------------------------------- |
| 探针页 probe         | 与最终纸张同尺寸的离屏测量容器，取正文可用高度、布局原始块            |
| 累加器 acc           | 隐藏的真实渲染容器，逐块/逐行/逐条带填充并实测溢出                    |
| 硬分段 segment       | 显式分页符切出的独立填页区间，分段间必然换页                          |
| 表骨架 chunk         | 放入 acc 的空 `<table>`（仅 colgroup + 空 tbody），逐行追加成页内表格 |
| 条带行 band          | 超高 `<tr>` 按单元格第 k 个子元素横向切出的子行                       |
| 页盒 .emr-print-page | 一张物理纸的 DOM：固定 mm 宽高 + 边距 padding + 页眉/正文/页脚三段    |
| 快速路径             | 整块 outerHTML 直接 tryAppend 成功，无需任何拆分                      |
